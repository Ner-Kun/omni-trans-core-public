# Архитектура

## Что где лежит

- `omni_trans_core/` — ядро. Лорбук-специфика должна жить в приложении; ядро даёт окно, настройки, провайдеры, очередь заданий, локализацию, уведомления и общий редактор промптов.
- `launcher/` — общий GUI-лаунчер. Ставит приложения в корень, обновляет их и запускает `runner.py` из общего venv.
- `lgt_app/` — отдельный репозиторий переводчика Lorebook Gemini Translator. В ядро не входит.

## Контракт приложения

Приложение даёт ядру шесть вещей:

1. `AbstractDataHandler` — загрузка/сохранение формата, список переводимых элементов, запись перевода.
2. `AbstractTab` — вкладки приложения.
3. `AbstractPromptFormatter` — как собирать промпт из элемента.
4. `AbstractResponseParser` — как разбирать ответ модели (опционально, есть `DefaultResponseParser`).
5. `PromptProfile` по умолчанию — промпты приложения (опционально; без него ядро использует нейтральный `Default`).
6. `DonationConfig` — донат-цель приложения (опционально; блок ядра добавляется сам).

Этого достаточно, чтобы новый переводчик не трогал ядро.

## Путь перевода

1. `CoreApp` загружает файл через `data_handler.load()`.
2. `data_handler.get_translatable_items()` отдаёт `TranslatableItem`.
3. `TranslationManager.prepare_jobs()` фильтрует кэш и собирает `JobData` на каждое активное подключение.
4. `LiteLLMStrategy` проверяет лимиты (общие и по модели) и решает, можно ли отправлять задание. При нескольких ключах `KeyPool` ротирует их и держит RPM/cooldown по каждому.
5. `CustomJobRunnable` вызывает API через litellm и парсит ответ. Gemini идёт тем же путём: `provider="gemini"`, модель `gemini/<model>`.
6. Успех: кэш, `item_translated`, обновление вкладки. Ошибка: retry, failover, автоотключение подключения после серии ошибок.
7. `CacheManager` хранит переводы рядом с файлом лорбука.

## Настройки

- `settings/global/` — общие для всех приложений: провайдеры, ключи, темы, язык интерфейса.
- `settings/<app_id>/` — настройки конкретного приложения и его профили промптов (`prompts/`).
- Дефолтный профиль промптов задаёт приложение; ядро даёт только нейтральный `Default`.
- Донат: ядро задаёт свой target, приложение — свой; диалог показывает оба блока.
- `settings/` в git не попадает. Секреты живут только локально.

## Интерфейс

- Только тёмная тема на QFluentWidgets: `MSFluentWindow`, `NavigationInterface`, карточки и Fluent-диалоги.
- `.ui`-файлов и QSS нет: интерфейс строится кодом, dev и релиз используют одни и те же виджеты.
- Уведомления — `InfoBar`, долгие операции — `StateToolTip`; старые тосты и overlay удалены.

## Правила разработки

- Коммиты — только после проверки. Пока первый коммит не сделан, история чистая.
- `lgt_app/` — вложенный репозиторий, корневой git его игнорирует.
- Обновление библиотек — по одной, с прогоном тестов после каждого шага.
